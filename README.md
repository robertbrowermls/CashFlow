# Daily Task Scheduler

This solution is a TypeScript Node.js application that runs a scheduled task every day and makes a trade, if possible, during that run.

## Overview

The application uses `node-cron` to schedule jobs. It reads its runtime settings from `config.json`, executes the trading logic, and sends email notifications on success or failure.

## What the app does

- Starts tasks using the cron expressions and settings in `config.json`
- Cancels orders that don't get filled
- Closes trades if they expire soon
- Closes trades when their price per day is too low
- Reads configuration from `config.json`
- Performs API calls to configurable endpoints
- Sends error notifications by email if the task fails
- Sends success notifications by email when the task succeeds
- Writes log messages to both the console and a file
- Supports standard console log levels: `debug`, `info`, `warn`, `error`, and `log`
- Uses a configurable authorization header for all API calls

## Project structure

- `src/index.ts` — app entry point that loads config and starts the scheduler
- `src/app/config.ts` — config loading and runtime configuration resolution
- `src/app/logger.ts` — console and file logging
- `src/app/api.ts` — GET and PUT API request logic
- `src/app/email.ts` — SMTP email error notifications
- `src/app/scheduler.ts` — cron scheduling and the daily task runner
- `config.json` — runtime configuration for schedule, endpoints, credentials, and payloads
- `package.json` — npm project metadata and dependencies
- `tsconfig.json` — TypeScript compiler configuration
- `dist/` — compiled JavaScript output generated by TypeScript
- `logs/` — application log files (created at runtime)

## Configuration reference

The following options are available in `config.json`:

| Field | Purpose |
| --- | --- |
| `appName` | The application name shown in logs and reports |
| `tradeSchedule` | Cron expression for when to execute trades; `* * * * 1-5` means every minute, Monday through Friday |
| `cancelOpenOrdersSchedule` | Cron expression for when to cancel open orders |
| `closeExpiringPositionsSchedule` | Cron expression for when to check and close expiring positions |
| `closePricePerDaySchedule` | Cron expression for when to check and close positions with low price per day |
| `timezone` | Time zone used by the scheduler |
| `minCashBalance` | Minimum cash balance required to place new trades |
| `marketTypes` | Array of market types to trade (e.g., `["stock"]`) |
| `exchangeCodes` | Array of exchange codes to filter stocks (e.g., `["N", "P", "Q"]`) |
| `maxStockPrice` | Maximum stock price to consider for trading |
| `getQuotesApiChunkSize` | Number of quotes to fetch per API call |
| `minAverageVolume` | Minimum average trading volume for a stock |
| `minSpread` | Minimum spread (bid-ask difference) in dollars |
| `maxSpread` | Maximum spread (bid-ask difference) in dollars |
| `minRor` | Minimum return on risk percentage (0.33 = 33%) |
| `maxTrades` | Maximum number of concurrent trades allowed |
| `priceAdjustment` | Price adjustment applied to orders (e.g., -0.02 = 2 cents lower) |
| `optionExpirationDays` | Number of days ahead for option expiration |
| `maxOrderAgeInMinutes` | Maximum age in minutes for open/pending orders before cancellation |
| `daysBeforeExpirationToExitPosition` | Days before expiration to automatically close positions |
| `percentPricePerDayToExitPosition` | Threshold percentage for price per day below which to exit (0.50 = 50%) |
| `apiBaseUrl` | Base URL for API requests |
| `authorization` | Bearer token for API authentication |
| `emailRecipients` | Email addresses for task notifications and alerts |
| `smtp.host` | SMTP server hostname |
| `smtp.port` | SMTP server port |
| `smtp.secure` | Whether the SMTP connection should use TLS/SSL |
| `smtp.user` | SMTP username |
| `smtp.pass` | SMTP password or app password |
| `smtp.from` | Sender email address used for notifications |
| `logging.level` | Minimum log level to emit; supports `debug`, `info`, `warn`, `error`, and `log` |
| `logging.file` | File path for the application log output |

## Logging

The app writes log output to both the console and a file.

- Configure the minimum level with `logging.level` in `config.json`
- Configure the destination file with `logging.file` in `config.json`
- If the file path is not set, the app uses `logs/app.log` by default

Example:

```json
{
  "logging": {
    "level": "debug",
    "file": "logs/app.log"
  }
}
```

## Cron expression guide

The `schedule` value uses the standard 5-field cron format:

- `minute` (0-59)
- `hour` (0-23)
- `day of month` (1-31)
- `month` (1-12)
- `day of week` (0-7, where 0 and 7 both mean Sunday)

Example: `0 9 * * 1-5` means:
- run at minute `0`
- at hour `9` (9:00 AM)
- every day of the month (`*`)
- every month (`*`)
- Monday through Friday (`1-5`)

## Runtime flow

1. The app loads `config.json` at startup and resolves runtime settings from the environment and config file
2. It starts the schedulers and runs the tasks immediately on launch for immediate visibility
3. It computes the GET URL using `stockSymbol` and the current date plus `optionExpirationDays` to determine the expiration date
4. It performs a GET request with:
   - `Accept: application/json`
   - `Authorization: Bearer <token>` (from config)
5. It performs a PUT request with:
   - `Accept: application/json`
   - `Content-Type: application/json`
   - `Authorization: Bearer <token>` (from config)
   - JSON body from `putPayload`
6. On error or success, the app sends an email to `emailRecipients`

## Getting started

### 1. Clone the repository

```bash
git clone https://github.com/robertbrowermls/CashCow.git
cd CashCow
```

### 2. Install dependencies

```bash
npm install
```

### 3. Configure the app

Edit `config.json` with your settings:
- SMTP credentials for email notifications
- API endpoint URLs and authorization token
- Scheduling preferences

### 4. Build the project

```bash
npm run build
```

### 5. Start the application

```bash
npm start
```

To run the web server:

```bash
npm run web
```
